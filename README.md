# Coreframe Comply

Retailer routing guides are long PDFs of shipping rules: carton limits, label placement, ASN timing, approved carriers, appointment windows. Break one and the retailer deducts a chargeback from the invoice. Mid-market 3PLs work to dozens of these guides, and they change often.

Coreframe Comply turns a routing guide into structured requirements with citations, then checks shipments against those requirements before they leave the dock.

**Design principle: the LLM extracts, code checks.** The model reads the guide and produces typed rules with page citations. A deterministic rule engine decides pass/fail. If the model can't map a rule to a checkable shipment field, the rule is marked `needs_human` and shown for review. The model never guesses a pass/fail.

> Work in progress: v0 is being built in phases. Phase 1 (ingestion + schemas) is done.

## Quick start

```bash
python3.11 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m coreframe ingest --guide data/sample/guides/northwind/v2025.1.pdf
.venv/bin/pytest -q
```

## Data

`data/sample/` holds a **synthetic** routing guide for a fictional retailer (Northwind Retail Co.), plus hand-written ground truth. It is generated by `scripts/build_sample_guide.py`. It's designed to exercise the hard cases: rules that live only in tables, a table split across pages, conditional rules, cross-references, a scanned page with no text layer, and rules that cannot be auto-checked.

Everything else under `data/` (real retailer guides, ground truth, model caches, outputs) is gitignored.
